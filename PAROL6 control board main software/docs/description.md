## 📁 Архитектура проекта

Прошивка состоит из следующих модулей:

```
parol6_firmware/
├── main.cpp              # Главный файл с setup() и loop()
├── adc.c/h               # Работа с АЦП для измерения напряжения
├── CAN.cpp/h             # Низкоуровневый драйвер CAN
├── coms_CAN.cpp/h        # Высокоуровневый CAN протокол
├── hw_init.cpp/h         # Инициализация аппаратной части
├── iodefs.h             # Определения пинов для родной платы
├── motor_init.cpp/h      # Инициализация структур двигателей
├── structs.h            # Структуры данных для робота и гриппера

├── constants.h          # Константы проекта
├── common.h             # Глобальные переменные времени

```

## 🔧 Подробный анализ файлов

### 1. **main.cpp** - Сердце системы

**Назначение**: Главный управляющий цикл, обработка команд, координация всех компонентов.

**Ключевые компоненты**:
- **6 шаговых двигателей** с драйверами TMC5160 (через SPI)
- **AccelStepper** для управления движением
- **CAN шина** для связи с гриппером (захватом)
- **Последовательный порт** (USB) для связи с ПК

**Основные функции**:
```cpp
void setup() {
    // Инициализация всего оборудования
    // Настройка драйверов двигателей
    // Запуск таймеров
    // Инициализация CAN и Serial
}

void loop() {
    // Чтение команд с ПК
    // Обработка команд (гоминг, движение, управление гриппером)
    // Отправка состояния робота обратно на ПК
}
```

### 2. **CAN система** (3-уровневая архитектура)

#### Уровень 1: **CAN.cpp/h**
- **Низкоуровневый драйвер** для контроллеров CAN1 и CAN2 STM32
- **Функции**: инициализация, настройка фильтров, отправка/прием
- **Скорость**: 1000 кбит/с
- **Фильтры**: настраиваются на прием всех сообщений

#### Уровень 2: **coms_CAN.cpp/h**
- **Протокол связи с гриппером** (11-битные CAN ID)
  ```
  Битовая структура ID: [3:0] - ID команды, [7:4] - ID узла, [10:8] - флаги
  ```
- **Команды гриппера**:
  - `60` - данные от гриппера (позиция, ток, статус)
  - `61` - управление гриппером (позиция, скорость, ток)
  - `62` - калибровка гриппера
  - `1` - сброс ошибок

#### Уровень 3: **Интеграция в main.cpp**
- Обработка в `CAN_protocol()`
- Отправка команд в `Handle_gripper()`

### 3. **Структуры данных** (structs.h)

#### MotorStruct - данные одного сустава:
```cpp
struct MotorStruct {
    // Конфигурация
    int motor_max_current;      // Максимальный ток (мА)
    int microstep;              // Коэффициент микрошага (32)
    float reduction_ratio;      // Передаточное отношение редуктора
    
    // Текущее состояние
    long position;              // Текущая позиция (шаги)
    int speed;                  // Текущая скорость
    int homed;                  // Флаг гоминга (0/1)
    
    // Пины управления
    int LIMIT;                  // Пин концевика
    int DIR;                    // Пин направления
    int STEP;                   // Пин шага
    int SELECT;                 // Пин выбора SPI (CS)
    
    // Параметры движения
    int standby_position;       // Позиция ожидания
    int homed_position;         // Позиция после гоминга
    int joint_range_positive_steps;  // Макс. позиция
    int joint_range_negative_steps;  // Мин. позиция
};
```

#### Robot - общее состояние:
```cpp
struct Robot {
    int command;                // Текущая команда (100=гоминг, 123=JOG и т.д.)
    int disabled;               // Флаг отключения (0=включен, 1=выключен)
    int Estop;                  // Состояние аварийной остановки
    int In1, In2;               // Цифровые входы
    int Out1, Out2;             // Цифровые выходы
};
```

#### Gripper - данные захвата:
```cpp
struct Gripper {
    // Текущие значения (от гриппера)
    int current_position;
    int current_current;
    int current_status;
    
    // Команды (к грипперу)
    int commanded_position;
    int commanded_speed;
    int commanded_current;
    int commanded_ID;           // CAN ID гриппера
};
```

### 4. **Инициализация двигателей** (motor_init.cpp)

Для каждого сустава (1-6) задаются уникальные параметры:

**Пример для Joint 1**:
```cpp
void Init_Joint_1(struct MotorStruct *Joint__) {
    Joint__->standby_position = 10240;     // Позиция ожидания
    Joint__->homed_position = 13500;       // Позиция после гоминга
    Joint__->motor_max_current = 2000;     // Макс. ток 2000мА
    Joint__->microstep = 32;               // 32 микрошага
    Joint__->reduction_ratio = 6.4;        // Передаточное 96:15
    Joint__->LIMIT = LIMIT6;               // Пин концевика
    Joint__->DIR = DIR1;                   // Пин направления
    Joint__->STEP = PUL1;                  // Пин шага
    Joint__->SELECT = SELECT1;             // Пин CS драйвера
    Joint__->direction_reversed = 1;       // Направление обратное
}
```

### 5. **Коммуникационный протокол с ПК**

**Формат пакета**:
```
[3 байта] 0xFF 0xFF 0xFF  - Стартовая последовательность
[1 байт]  Длина данных     - 56 байт для полного пакета
[18 байт] Позиции 6 осей   - по 3 байта на ось
[18 байт] Скорости 6 осей  - по 3 байта на ось
[1 байт]  Команда          - 100=гоминг, 123=JOG и т.д.
[1 байт]  Целевой сустав   - Для точечных команд
[1 байт]  Входы/Выходы     - Битовое поле
[1 байт]  Таймаут          - 0=отключен, 255=255мс
[8 байт]  Данные гриппера  - Позиция, скорость, ток, команда
[1 байт]  CRC              - Контрольная сумма
[2 байта] 0x01 0x02        - Конечная последовательность
```

**Команды управления**:
- `100` - Гоминг (поиск нуля)
- `101` - Включить робота
- `102` - Выключить робота
- `103` - Сброс ошибок
- `123` - Режим JOG (ручное управление)
- `156` - Движение к позиции
- `255` - Dummy команда (остановка)

### 6. **Процедура гоминга** (home_all())

**Сложная последовательная процедура**:
1. **Этап 1**: Гоминг осей 1,2,3 одновременно
2. **Этап 2**: Гоминг оси 4
3. **Этап 3**: Гоминг оси 6
4. **Этап 4**: Гоминг оси 5
5. **Финал**: Возврат в позиции ожидания

Каждый этап имеет несколько стадий для точного позиционирования.

## 🔄 Как все работает вместе

### Последовательность запуска:
1. **Инициализация аппаратуры** (пины, SPI, АЦП)
2. **Настройка драйверов TMC5160** через SPI
3. **Запуск таймеров** для отсчета времени
4. **Инициализация CAN и Serial**
5. **Главный цикл**:
   - Чтение команд с ПК
   - Обработка CAN сообщений от гриппера
   - Выполнение команд движения
   - Отправка состояния обратно на ПК

### Поток данных:
```
[ПК] → Serial → main.cpp → обработка → двигатели/гриппер
                                    ↓
[гриппер] → CAN → coms_CAN → main.cpp → Serial → [ПК]
```
